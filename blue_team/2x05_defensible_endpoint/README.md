# 2x05 Defensible Endpoint

This MedDefense capstone brings Linux and Windows hardening, endpoint telemetry, patch management and network defence together at the Hawthorne site. The workflow starts with an inventory and baseline, defines the controls both endpoints must satisfy, and builds a handoff package that the next engineer can verify independently.

## Lab scope

The target endpoints are `hawthorne-app-01` (Linux) and `hawthorne-adm-01` (Windows). The supplied inputs under `/home/analyst/MedDefense_Lab/capstone/` include the CVE feed, the segmentation policy, the DNS blocklist and the packet captures.

The Task 8 script writes `capstone/validation_report.json`, the artefact referred to as `validation.json` in the capstone review. Windows command checks use evidence collected on the Windows endpoint, and missing evidence is recorded as an error.

## Review answers

### Task 12 — The Module Synthesis

Linux and Windows hardening reduce exposure on both hosts, patching fixes known vulnerabilities in the software they still need, and segmentation limits who can reach the services that remain. Auditd and Sysmon show what happened on each host, and offline Suricata replay checks whether the network signatures detect the expected activity in labelled captures. The order matters because the baseline captures the original state and telemetry needs to be active before patching so engineers can trace any regressions. Defining the required network flows before enforcing segmentation also helps preserve administrative access and connectivity to update repositories. Structured JSON reports give the validation suite consistent fields and evidence paths, so it can link each control to a hardening score, patch outcome or detection result. The target state defines what the whole environment must satisfy for handoff, and the validation suite blocks handoff if any control fails or lacks evidence. If telemetry were omitted, operators would lose the event trail they need to verify that controls are working and investigate suspicious activity or a service failure after patching.

### Task 13 — Binary Evaluation

Binary checks give the receiving team a repeatable way to decide whether a production handoff meets the agreed requirements and to pinpoint what needs fixing. They can verify specific facts, such as which firewall rules are loaded, whether a patch report records zero failures, or whether a Suricata rule fired on its labelled capture. A pass only covers the condition tested, so a correct rule count leaves questions about detection coverage and whether legitimate traffic can still get through. Tying each verdict to a control ID, host, timestamp and raw output makes gaming harder because a reviewer can cross-check the reported result against the underlying evidence and rerun the test. Professional judgement is still needed to decide whether the controls fit the site’s risks, whether exceptions are justified and what risk remains. The capstone uses the target state and validation suite to enforce measurable handoff criteria, while the design rationale and runbook explain the engineering decisions and guide the response to failures.

### Task 14 — The Handoff That Outlives You

A professional security handoff lets the receiving engineer rerun the checks, trace failures and take ownership of the environment independently. Task 2’s `target_state.json` defines the required controls and their pass criteria, so removing it would erase the benchmark for verification. Task 8’s `validation.json` records each control’s pass, fail or error verdict and its evidence path, so removing it would lose the record of what was actually verified. Task 10’s `compliance.json` summarises the assessed security posture and outstanding gaps, so removing it would make it harder to see which requirements still need attention. Task 11’s `manifest.json` lists the expected files and their SHA-256 hashes, so removing it would take away the reference for detecting missing or altered artefacts. I’d prioritise `validation.json` for the incoming Module 3 analyst because its verdicts and evidence show whether checks such as loaded audit rules and recent Sysmon events passed, giving the analyst a basis for trusting Hawthorne’s telemetry and recognising collection gaps from day one.
